About

This tracker answers one question: is there a detection for this yet? It watches three of the most widely used open detection-rule repositories and cross-references every rule against recent CVEs and MITRE ATT&CK techniques, so you can check coverage before you write a rule from scratch — or find the gap before an attacker does.

Methodology

CVE and ATT&CK references are read directly from each rule's own metadata where the source provides structured fields (Splunk ESCU's cve:/mitre_attack_id:, Elastic's [[rule.threat]] tables, Sigma's attack.* tags). Where a source has no structured CVE field — notably Sigma and Elastic, which usually only mention a CVE in the rule's title or description — this tracker falls back to pattern-matching CVE IDs out of that text. That fallback is marked as lower-confidence internally, though it's shown the same way in the UI since in practice it's reliable for well-formed rule titles.

A "coverage gap" is a CVE published (or added to CISA's KEV catalog) within the selected window that no non-deleted rule in any of the three sources currently references. It is not proof that no detection exists anywhere — only that none of these three repos has shipped one yet.

Rule repos are polled every {{ settings.rules_poll_interval_minutes }} minutes (configurable) via local git clones, diffed against the last processed commit. CVE data comes from the NVD API and CISA KEV. ATT&CK technique data comes from MITRE's STIX data.
